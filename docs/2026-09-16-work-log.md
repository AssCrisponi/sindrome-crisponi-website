## 2. Homepage / slideshow layout investigation
Investigated why the two slideshow images rendered at different sizes and had no visible gap between them.

- **Dead CSS removed**: a leftover `.img_content` rule in `home.css` was a no-op (overridden by `imagebox.css`, imported later in the module graph) — removed to avoid confusion; `imagebox.css` is now the single source of truth for `.img_content` styling.
- **Root cause of size mismatch**: the two images (`dona.jpg`, `cinque_x_mille.png`) had different native aspect ratios, but the CSS forced a single `aspect-ratio` on the `<img>`, causing inconsistent letterboxing.
- **Root cause of "no gap"**: the `react-slideshow-image` library sets each slide's width via inline JS (`eachDiv.style.width = ...px`), which overrides stylesheet widths. Adding `margin` would have broken the library's internal slide-position math. Fixed instead with `padding` + `box-sizing: border-box` on `.each-slide-effect`, which is safe because border-box keeps the inline pixel width representing the full box (padding included).

## 3. Equalizing slideshow image sizes

- Updated `imagebox.css`'s `aspect-ratio` from an arbitrary `4/3` to the real matched ratio `1001/707`.
- When the user still saw mismatched sizes after the fix, verified via a clean production build (`CI=true npm run build`) that both images bundle correctly at 1001×707 with fresh content hashes — concluded the issue was a stale dev server / browser cache, not the fix itself.
